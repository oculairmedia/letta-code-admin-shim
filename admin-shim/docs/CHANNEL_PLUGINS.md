# Channel Plugins

Channel plugins are user-authored `.mjs` files that live at
`~/.letta/channels/<channelId>/plugin.mjs`. The admin-shim discovers them at
runtime (no build step, no registration) and imports them as ES modules. Two
reference plugins ship in this repo: `home/.letta/channels/mobile/plugin.mjs`
(inbound WS) and `home/.letta/channels/matrix/plugin.mjs` (outbound long-poll).

## Minimal plugin shape

A plugin exports `channelPlugin` (or `default`) with a `createAdapter` factory:

```js
export const channelPlugin = {
  metadata: { id: "myChannel", displayName: "My Channel" },

  async createAdapter(account, host) {
    return {
      id:        `myChannel:${account.accountId ?? "default"}`,
      channelId: "myChannel",
      accountId: account.accountId,
      async start() { host.log?.("started"); },
      async stop()  { host.log?.("stopped"); },
      isRunning()   { return true; },
    };
  },
};

export default channelPlugin;
```

The `host` argument exposes the bridge into the shim's worker pool:

| Member | Purpose |
| --- | --- |
| `host.log(msg)` | Line logger; routes through the shim's logger. |
| `host.getServerId()` | Server identity string for handshake / welcome frames. |
| `host.bridgeSendMessage(args, onFrame, hooks?)` | Dispatch a user message into the worker pool. Streams reshaped wire frames via `onFrame`. Resolves when the turn settles. |
| `host.cancelRun(runId)` | Best-effort cancel; returns `true` if a run was canceled. |

## Opt into type hints

The shim ships a TypeScript declaration that captures this contract:
`admin-shim/dist/lib/types/channel-plugin.d.ts`. Plugin authors can opt in by
adding a triple-slash reference at the top of their `.mjs` file and annotating
exports with JSDoc:

```js
/// <reference path="../../../admin-shim/dist/lib/types/channel-plugin.d.ts" />

/** @type {import("../../admin-shim/dist/lib/types/channel-plugin").ChannelPlugin} */
export const channelPlugin = {
  metadata: { id: "myChannel" },

  /** @param {import("...").ChannelAccount} account
   *  @param {import("...").ChannelHost} host */
  async createAdapter(account, host) {
    /** @type {import("...").ChannelAdapter} */
    const adapter = {
      id: `myChannel:${account.accountId ?? "default"}`,
      channelId: "myChannel",
      accountId: account.accountId,
      async start() { host.log("ready"); },
      async stop()  { /* … */ },
      isRunning()   { return true; },
    };
    return adapter;
  },
};
```

The path is relative to the plugin's own `.mjs`. The
`admin-shim/dist/lib/types/channel-plugin.d.ts` file is generated by
`npm run build` in `admin-shim/` — it does not exist in the source tree.

## Interfaces

The declaration file exports three core interfaces:

- `ChannelPlugin` — the module-level `channelPlugin` export. Holds
  `metadata`, `createAdapter`, and optional `messageActions`.
- `ChannelAdapter` — the object returned by `createAdapter`. `start` / `stop`
  / `isRunning`, plus optional `sendMessage`, `sendDirectReply`, `onMessage`,
  and (for inbound WS plugins) `acceptConnection`.
- `ChannelHost` — the bridge object the host hands to `createAdapter`. See
  the table above.

Mobile-specific bits (`acceptConnection`) live in a `MobileChannelExtras`
sub-interface and are optional on the generic adapter.

## Types are optional

The host loads plugins via runtime duck-typing: it imports the module as
`unknown` and only checks that `createAdapter` is a function. Plugins that
don't reference the `.d.ts` keep working exactly as before. The types exist
solely to help authors who want editor hints.
